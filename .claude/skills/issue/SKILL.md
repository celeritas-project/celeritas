name: issue
description: Submit a GitHub issue to Celeritas through the API or gh CLI with the required authorship, type, and labels. Use whenever an agent files an issue.
---

Issue forms are not enforced for API requests, so mimic the form body and use
the `issues_opened` workflow's commands to set the type and labels. The valid
types and labels are defined in `.github/workflows/issues_opened.yml` (`config`)
(`kinds`, `allowedLabels`): check them there before filing.

## Body format

```
### Authorship

Generated by AI

### Celeritas configuration      <- bug reports only, required

{ ...JSON output of `celer-config`... }

### Description

<description>

@github-actions type bug
@github-actions label geometry

Generated with <agent identity: driver, agent, model>
```

- `Authorship` must be `Generated by AI` (the workflow adds `ai-generated`).
- Commands are one per line, alone on the line:
  `@github-actions type <enhancement|bug|task>` (exactly one) and
  `@github-actions label <label>` (zero or more allowed labels).
  Processed commands are turned into HTML comments; unrecognized ones get a
  reply comment.
- Bug reports need the `celer-config` JSON (the workflow wraps it in a
  `json` code fence).
- End with a "Generated with" statement naming the agent identity.
- Use `gh issue create --repo celeritas-project/celeritas --title ... --body-file ...`
  and never invent labels outside the allow-list.

Every comment you later post on the issue must disclose the harness/model and
contain a clear-text 🤖, e.g. `🤖 (Claude Code, Sonnet 5.5)`.
